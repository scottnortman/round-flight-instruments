# v0.2.0-rc.1 - MSFS two-way checkpoint

This source checkpoint adds MSFS 2020 altimeter input and optional two-way
barometer control to the standalone v0.1.1 baseline. It is a bench-tested release
candidate, not a general aircraft compatibility or flight-accuracy claim.

- Simulator-independent quantities, validity, freshness and channel definitions
  support future gauges and adapters; the current transport carries altimeter data.
- Native SimConnect adapter, synthetic/replay providers and UART relay with
  CRC/sequence/session validation, unique logs and completed-frame diagnostics.
- Read-only by default; opt-in barometer requests change the displayed setting
  only through simulator readback. Pending writes are correlated and bounded.
- Incremental QNH rendering avoids rebuilding the entire dial for pressure edits.
  A rapid-QNH board benchmark averaged 31.72 completed presentations per second.
- Paused/loading heartbeats do not make old numeric readings fresh.

Validation: 102 native-enabled Rust tests, all-target Clippy with warnings denied,
Rust formatting, and six Python integration tests pass. The integration firmware
was built, installed and exercised on Waveshare SKU 29086. Live Just Flight Piper
Warrior testing confirmed four barometer writes; all 7,012 frames in that run
passed CRC, sequence and ACK checks. See [evidence](../../verification/MSFS-NATIVE.md).

Aircraft, flight and position changes deliberately end the bridge session.
After loading and unpausing the next flight, restart the bridge using the
[setup guide](../MSFS-TWO-WAY-TEST.md). Automatic recovery, a packaged Windows
application, DCS and additional hardware gauges remain future work. Full
climb/descent accuracy, all failure paths and other aircraft require acceptance.

No new public binary asset is published by this checkpoint. The previously
delivered `barometer-two-way-v2` test package and installed board firmware remain
the tested binaries; no reflash is needed. The v0.1.1 public ZIP is standalone only.
